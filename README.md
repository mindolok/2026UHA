# 여기타 CITY FLOW — 지도 웹 + 최종 엔진

## 실행
```
python -m venv .venv
.venv\Scripts\activate            (Mac: source .venv/bin/activate)
pip install -r backend/requirements.txt
cd backend
uvicorn main:app --port 8000
```
브라우저에서 http://localhost:8000. `.env`(KAKAO_JS_KEY, KAKAO_REST_KEY)는 이 폴더 바로 아래에 둡니다.

엔진 테스트: `cd engine` → `python -m unittest discover -s tests` (26개)

### 새 행사 공지 넣기 (v1 CSV 형식)
```
cd engine
python -m cityflow load-v1 --db cityflow.db --active data/events/<행사>_v1_active.csv
```
서버를 다시 켜면 반영됩니다. `*_active.csv`만 씁니다(`hold`, `우회경로`는 쓰지 않음).

## 구성
| 위치 | 역할 |
|---|---|
| `engine/cityflow/planner.py` | **최종 엔진.** 순번 기반 통제 판정, 승·하차 무정차 분기, 통제 반영 경로 탐색 |
| `engine/cityflow/` 나머지 | 업로드받은 v2 구현(데이터 적재, 기존 판정·가지치기). 변경 없음 |
| `engine/cityflow/v1csv.py` | 팀 v1 CSV(`*_active.csv`) 로더. 열 이름으로 읽고 ID는 문자열 유지 |
| `engine/cityflow.db` | 노선 41,688행 · 정류소 11,236행 · 공지 `jtbc_v1_active.csv` 2,720행 |
| `engine/data/events/` | 공지 CSV 원본 |
| `engine/cityflow/subway.py`, `engine/data/subway/` | 지하철 1~8호선(서울교통공사 역간 소요시간·역 좌표·역명 변경, UTF-8 변환본) |
| `backend/` | FastAPI. `/api/stop`, `/api/route`, `/api/controls`, `/api/search`(카카오 장소검색) |
| `frontend/` | 카카오맵 화면. "내 버스 확인" / "길찾기" 탭 |

## 팀 결정 반영 (2026-11-21)
- 공지 데이터: 팀 v1 CSV의 `active`만 사용(2026-11-21 인수인계). `hold`(9행)와 `우회경로`(좌표 있는 지점 23%)는 사용하지 않음.
- 공지 매칭: `(노선, 정류소순번)` — 순번 있는 2,627행 전부 노선 데이터와 일치. 방향 문구는 표시용.
- 순번이 빈 93행(방향 추정 + 반대편 같은 이름 정류소): 판정·길찾기에 쓰지 않음. '내 버스 확인'에서 그 정류장을 조회할 때만 "방향이 불확실한 무정차 공지가 있음" 주의 문구를 표시.
- T0* = 평소(통제 무시) 최단 시간, 고정. T0*+60분 초과·환승 5회 초과는 제외(경계값 허용).
- 무정차 구간 통과: 공지 묶음당 **+10분(추정)** 한 번.
- `확인 필요` 631행: 통제로 간주. 그 구간을 지나는 경로는 "확인 필요" 칸으로만 표시.
- 승차 정류장 무정차 → 같은 노선 직전·다음 정상 정류장까지 도보. 하차 무정차 → 직전 정류장에서 내리거나 합류 정류장까지 타고 감.
- 종료시각구분 `통제해제시` 96행: 공지 최대 종료시각+20분(14:30)까지로 추정.

## 지하철 (2026-11-21 추가)
- 1~8호선을 버스와 같은 탐색에 포함. 화면의 '지하철 포함'을 끄면 버스만으로 탐색.
- **지하철은 교통통제 영향 없음**(통제 판정 대상 아님).
- 소요시간: 서울교통공사 역간 표준 운행시간 + 역 정차 30초. 대기 4분, 하차 후 출구 이동 2분(추정). 환승역은 같은 역명끼리 도보 연결(최소 150m).
- 노선 모양: 2호선 외선·내선 순환(1.5바퀴), 성수·신정 지선은 별도 운행. 5호선 마천지선은 방화부터 직통. 6호선 응암 순환은 한 방향.
- 좌표 파일 오류 보정: 잠실새내(잠실나루와 같은 좌표), 발산(마곡과 같은 좌표), 신답은 앞뒤 역 사이를 역간거리 비율로 보간. 용답은 신답 칸에 있던 좌표 사용.
- 빠진 것: 8호선 암사역사공원(좌표 없음), 9호선·신분당선·공항철도·경의중앙선 등(데이터 없음).

## 계획서(CITYFLOW_algorithm_v2) ↔ 구현
| 계획서 단계 | 구현 (`planner.py`) |
|---|---|
| 원래 경로 탐색, T0* = 원래 경로 최솟값(고정) | `search()` 1단계: 통제 무시 탐색을 노선 제외 반복으로 여러 개 생성, 최단을 T0*로 고정 |
| 원래 경로를 정류장 역할별로 순차 검사 | `check_original()`: 승차/환승승차/경유/환승하차/하차마다 통제 판정 → OK / DELAYED(경유 무정차, +10분) / BLOCKED(승·하차 무정차) / CHECK |
| 승차 무정차 → 같은 노선 앞·뒤 정류장 도보 | `_raptor()` 출발 분기(`pivots`) |
| 하차 무정차 → 직전 정류장 하차 / 계속 타고 합류 정류장 | `_raptor()` 도착 분기 + 경유 통과 허용 |
| 경유 무정차 → 분기 없음, 지연만 | 경유 통과 시 공지 묶음당 +10분(추정) 1회 |
| 재탐색(다른 노선·근처 정류장) | 같은 탐색 안에서 300m 환승 도보·다른 노선 포함, 노선 제외 반복으로 후보 다양화 |
| 가지치기 A(+60분) B(환승 5회) | 경계값 허용, 탐색 중 예산 초과 시 중단 |
| 가지치기 C(하한) D(우월 상태) | C는 직선÷25km/h가 허용 하한이 아니라 미적용(경과시간 기준만), D는 탐색의 정류장별 최단 도착으로 대체 |
| 미검증 통제 = 통제됨 + 확인 필요 | 엄격 탐색(확정) / 완화 탐색(확인 필요) 분리 |
| 파레토 순위화 | `_pareto_rank()`: (시간, 환승, 도보) 비지배 정렬 → 상위 5개 |
| 평소 대비 비교 | `compare()`: 시간·환승·도보 차이, 빠진/새 버스, 타는·내리는 곳 변경, 피한 무정차 |

## 추정값 (`planner.Assumptions`)
노선 자료에 시간표가 없어 소요시간은 모두 추정입니다. 버스 17km/h(직선×1.3)+정차 20초, 승차 대기 6분, 도보 1.2m/s(직선×1.2), 환승 도보 300m, 출발·도착 반경 400m, 심야(N·심야) 23:00~05:30, 새벽버스 03:30~07:00.
